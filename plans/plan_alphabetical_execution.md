## 一、执行原则

### 1.1 为什么按字母顺序？

✅ **系统性强**: 按固定顺序，不会遗漏
✅ **进度清晰**: 容易跟踪完成情况
✅ **易于管理**: 简单直观的执行计划
✅ **避免混乱**: 不需要判断优先级

### 1.2 执行规则

**每个模块必须**:
1. ✅ 完成所有接口实现
2. ✅ 编写完整测试用例
3. ✅ 测试覆盖率 > 80%
4. ✅ 所有测试通过
5. ✅ 更新模块文档

**完成标准**:
- 编译通过
- 测试通过
- 文档完善
- 代码审查通过

## 五、每个模块的标准流程

### 5.1 开发流程（每个模块）

**第一步：规划（0.5小时）**
```bash
1. 创建模块计划文档 plans/plan_{模块名}.md
2. 分析 Python 源码
3. 列出接口清单
4. 设计数据结构
```

**第二步：实现（主要工作）**
```bash
1. 创建 {模块名}/doc.go
2. 创建 {模块名}/types.go
3. 实现所有接口函数
4. 遵循代码规范
```

**第三步：测试（工作量的30%）**
```bash
1. 创建 {模块名}/{模块名}_test.go
2. 为每个接口编写测试
3. 确保测试覆盖率 > 80%
```

**第四步：验收（0.5小时）**
```bash
1. go build -buildvcs=false ./...
2. go test -v ./{模块名}/...
3. go test -cover ./{模块名}/...
4. 更新进度文档
```

### 5.2 代码规范

**文件命名**:
```
{模块名}_{业务}_{数据源}.go
```

**函数命名**:
```go
// Python: air_quality_hist()
// Go: AirQualityHist()
```

**HTTP 调用**:
```go
headers := map[string]string{
    "Referer": "https://example.com",
}
resp, err := utils.GetWithHeaders(url, params, headers)
```
